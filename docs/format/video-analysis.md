# Video analysis controls

Status: controlled observations from Filmora 15.6.4.11894 on macOS. These are
not an official Wondershare schema, and analysis caches can be regenerated by
Filmora.

## Stabilization

On a disposable type `1` visual clip, enabling Video > Basic > Stabilization
changed only the existing clip object:

```json
{
  "cache_mode": 0,
  "smooth": 5.0,
  "status": 0,
  "version": 1.0
}
```

to the same object with `status: 1`. Repeating Smoothness from `5.0` to `9.0`
changed only `stabilization.smooth`. `stabilizeAnalysisData` remained null in
both saves. The two UI saves passed `eval-format`.

The low-level `replace_clip_stabilization` writer is deliberately narrow. It
requires one selected type `1` clip with exactly this enabled shape and only
replaces an existing smoothness value in the inclusive `0..10` range. It does
not insert Stabilization, run analysis, fabricate `stabilizeAnalysisData`, or
toggle the status flag. A generated `5.0 -> 9.0` copy opened in Filmora,
survived Save As, and retained `smooth: 9.0`; UIDs and other save metadata were
regenerated as expected.
